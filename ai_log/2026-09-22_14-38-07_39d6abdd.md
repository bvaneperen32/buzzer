## On overhead: right, but it's the secondary benefit

HTTP has solved the connection-reuse problem on its own. With keep-alive (default since HTTP/1.1), a browser already reuses one TCP connection across many requests, so you're not re-doing the TCP and TLS handshake every time anyway.

What a WebSocket still saves is **per-message** overhead: an HTTP request carries a full set of headers — cookies, user-agent, auth token — on every single call, often several hundred bytes to ask a one-byte question. A WebSocket frame is ~2-6 bytes of framing over the payload. You also authenticate **once** at connect ([middleware.py:12](backend/app/websocket/middleware.py#L12)) rather than validating a JWT on every message.
