## What a WebSocket is

Normal HTTP is a vending machine: the client asks, the server answers, the connection closes. The server has no way to speak first. If a browser wants to know "has the host started the next question yet?", plain HTTP forces it to keep asking — polling — which is slow and wasteful.

A **WebSocket** is a connection that starts as an ordinary HTTP request, then "upgrades" into a long-lived, two-way pipe that stays open. Either side can send a message at any moment, and the other side gets it immediately. That's the whole trick: the server can push.

This project doesn't use raw WebSockets directly — it uses **Socket.IO** on top of them (`python-socketio` on the backend, the `socket.io-client` in the browser). Socket.IO adds three things that matter here:

- **Named events** instead of a raw byte stream — you `emit("new_question", {...})` and the other side listens for `"new_question"`.
- **Rooms** — a server-side grouping so you can broadcast to "everyone in room A
