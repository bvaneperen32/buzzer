## Backend facts the frontend depends on

The backend matches spec Â§5.6. The details you'll need:

- **Error bodies** come in three shapes:
  - App errors: `{"error": code, "message": str}`.
  - Request-validation 422: `{"error": "VALIDATION_ERROR", "detail": [{msg, â€¦}]}`.
  - UnprocessableError 422: `{"error": "UNPROCESSABLE", "message": str}`.
- **Auth and listings:**
  - `GET /api/auth/me` returns `{id, username, netid, display_name, role}`. Any valid token works; a bad or expired token gets 401. A guest token returns `role: "GUEST"`.
  - `GET /api/game/my-courses` returns `[{id, name, semester, role}]`. Admins get every course; others get only courses they HOST.
  - `GET /api/game/my-games` returns `[{id, title, description, max_players, course_id, course_name, course_semester}]`, ordered by course name, semester, then title. Admins also get unassigned games, with the three course fields null.
- **Rooms:** `POST /api/game/rooms` accepts `allow_guests` (default true). A mismatch returns 409 "This game belongs to a different course".
- **Host downloads:**
  - Someone who isn't the session's live host gets 403 "Only the session's host can download it".
  - A session that isn't COMPLETED gets 409 "Downloads are available once the session has completed", even for admins.
- **Questions:** deleting an answered question returns 409 "This question has been
  answered in N session(s) and can't be deleted â€” edit it instead, or export the
  game and import a copy."
- **Guests:** `POST /api/auth/guest` to a room with guests disabled returns 403 "This game isn't open to
  guests â€” sign in with your school account".
- **Game delete:** there is no `DELETE /api/host/games/{id}` (it returns 405). Admins delete through
  `DELETE /api/admin/games/{id}`, and move games with `PUT /api/admin/games/{id}` and `{course_id}`.
