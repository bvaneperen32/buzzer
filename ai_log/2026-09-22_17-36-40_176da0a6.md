## How role-based access is enforced

All enforcement happens on the backend, in three layers. The frontend enforces nothing: every route guard only checks that a token exists.

### Layer 1: authentication
[`get_current_user`](backend/app/common/dependencies.py#L31) runs on every protected request:
- It reads the JWT from the `Authorization` header (or an `access_token` cookie) and accepts `access` or `temp` tokens.
- It reloads the `User` from the database each time. The token contains a `role`, but it's ignored, so a role change applies on the next request.

### Layer 2: account type, checked per endpoint
`User.role` is one of `ADMIN`, `USER` or `GUEST`. Two FastAPI dependencies check it:

| Guard | Rule | Used on |
|---|---|---|
| `require_admin` | role is `ADMIN` | all of `/api/admin/*` |
| `require_user` | role is not `GUEST` | all host endpoints in `/api/game/*` |
| `get_current_user` only | anyone signed in, guests included | e.g. `GET /api/game/rooms/{code}` |
